## 四、原著引用怎么核

`skill_book` 里每条的 `novel` 只有两种合法形态：

- `第X章「章节标题」 —— 原文连续片段`
- `原著无载 · 游戏自设`

**章号不许自己推**。上一版就是按剧情位置估的，184 条里只有 17 条章号对得上，116 条错、52 条正文压根没这技名。
现在的核法：

```bash
python src/plugins/doupo/_verify_novel.py            # 三态统计（VERIFIED / WRONG_TITLE / NOT_IN_NOVEL）
python src/plugins/doupo/_verify_novel.py --pick 黄泉天怒   # 单条看全文命中
python src/plugins/doupo/test_skill_book.py          # 引文必须能在正文里 find 到，否则 FAIL
```

语料：`C:/Users/L/AppData/Local/Temp/chaps`（2133 个页面 → 清洗成 1608 章），可用
`DOUPO_NOVEL_DIR` 指到别处。清洗做了三件事，都是踩过坑才加的：

1. **剔空壳页**：目录里有 495 个只有导航的壳（标题与正文页差一个字），按正文 <200 字丢弃；
2. **还原 `『X』`**：站方反爬把单字包起来（"炼『药』师"），不还原就搜不到"炼药师"；
3. **章号规范化**：站点是多卷制、章号每卷重置，且部分标题缺「一」（"第百二十章"），
   引用统一用 `int2cn(vol_no)` 重建（→"第一百二十章"）。

还有一处没法修的：站方用 `**` 吞了少量字（「六合游身尺」正文作 `**游身尺`），
所以引文里**禁止出现 `*`**，遇到就往上下文避开。

## 五、血泪教训（别重犯）

1. **`factions.py` 的 `skills` 是字符串，里面有 `A / B / C` 合并写法。**
   任何 `split("/")[0]` 的解析都会把后两个技静默丢掉 —— 原来的 `skills._skill_name()`
   就是这么丢了约 70 门斗技。现在游戏目录一律走 `skill_book`，字符串路径只作兜底。
2. **「有来源」不等于「有描述」。** 只写出处、不写怎么施展/打多少/什么限制，就是没写。
3. **卡片只有两行位。** 完整说明进 `斗技详情 <技名>`，卡片放 `brief`（≤24 字）。
   别再往卡片 desc 里塞长文 —— `test_descriptions_never_wrap_beyond_two_lines` 会拦。
